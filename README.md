# 待办捞捞机 🐟

把群聊文字粘进网页，AI 提取待办、负责人、截止时间和支持判断的原话。已确定要做但尚无负责人时显示“待认领”；责任归属互相矛盾时显示“待确认”。生成后可修改各字段、勾选进度、筛选状态、手动补充、复制清单或下载 CSV。这是一个零依赖的 Cloudflare Worker ES Module 项目，也可用 Node.js 在本机运行。

## 在线体验

打开部署地址后点“看看示例结果”，无需密钥。要分析自己的聊天记录，填写自己的 DeepSeek API Key，再点“用 AI 捞待办”。密钥只在本次请求中传到 Worker，再转发至 DeepSeek；默认不保存聊天记录；只有点击“保存到本机”后，聊天和清单才写入当前浏览器的 localStorage，后续修改自动保存。密钥不会保存，也没有服务器数据库。模型调用可能产生费用。

**注意：**示例结果是预设演示数据，只有“用 AI 捞待办”才会发起真实模型请求。

## 本地运行

需要 Node.js 20+。项目没有 npm 依赖。在项目目录执行：

```bash
node dev.mjs
```

访问 http://localhost:8787 。示例体验无需配置；真实提取需在页面临时填写自己的 DeepSeek API Key。项目代码在 `worker/index.js`，服务端请求 `POST /api/extract`，请求体为 `{"text":"聊天记录"}`，请求头为 `x-api-key: sk-...`。

## 输入聊天记录

可直接粘贴文本，或导入 1 MB 以内的 UTF-8 `.txt` / `.md` 文件。页面实时显示行数、字数，并提示可能出现的中国大陆手机号和邮箱；点击“隐去手机号/邮箱”会替换识别到的内容，随后可以撤销。它不会识别所有隐私信息，姓名、地址等仍需自行检查。文件只在浏览器读取，点击“用 AI 捞待办”后才会把文本发送给模型。超过 8,000 字时需先截取一段讨论，页面不会静默截断。

## 无人认领的任务

“车票还得买，谁来负责？”会被列为“购买车票｜待认领”，不会被改成“确认谁来买票”。在结果卡的负责人输入框中填入名字，就完成分配。单纯试探的“要不要买票？”不应列为确定待办。模型可能误判，请依据原话核对。

## 本机草稿与撤销

点击“保存到本机”后，当前聊天与清单会保存在这台设备的当前浏览器中；刷新可恢复。点“清除本机记录”只删除浏览器中保存的草稿，不立即清掉页面内容。未保存时页面会提示刷新将丢失，替换已有清单时会询问。删除待办后可在 8 秒内撤销。点击“查看原话”会定位并选中输入框里的对应内容。

## 结果复核

新版会把尚在讨论或已取消的事项放在“AI 未列入待办”折叠区，用户可点“改为待办”纠正判断。模型提供的原话如果无法在输入中逐字找到，会出现“原话未匹配，请核对”的提示。复制前应先审这些提示。

本地检查：`npm test`、`npm run build`、`npm run validate`。测试使用模拟模型响应，不代表真实模型的语义准确率。

## 使用边界

- 输入上限 8,000 字，最多展示 12 条待办。
- AI 可能误解聊天语气或任务归属。复制清单前请核对原话和日期。
- “明天”等相对时间保留原文；不会自动换算成日历日期。
- 建议先去掉电话、地址等隐私内容，再发送给模型。
- 当前没有账号、跨设备同步或自动提醒功能。未开启本机保存时，刷新页面会清空当前清单。

## 技术实现

单文件 HTML/CSS/JavaScript 前端 + Worker 服务端。服务端调用 DeepSeek Chat Completions 的 JSON Output，将结果校验为 `tasks`、`excluded` 和 `notes` 后返回。界面使用 DOM 的 `textContent` 渲染聊天内容，避免把模型输出当 HTML 执行。
